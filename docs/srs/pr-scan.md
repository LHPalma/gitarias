## 1. Introdução

### 1.1 Propósito

Especificar o **`gtr pr scan`**: procura atribuição de autoria de IA no título e no corpo dos pull requests do repositório, onde o `gtr ai-trailers list` — que só lê trailer de commit — nunca teria como ver.

### 1.2 Por que o `ai-trailers list` não bastava

Três propriedades do que faltava, cada uma medida antes de virar decisão:

| Propriedade | O que significa aqui |
|---|---|
| **A superfície era outra** | O corpo de um pull request não está no `git`: não é commit, não é blob, não vem no clone. Buscar a primeira frase do corpo de um PR deste repositório nos objetos alcançáveis do próprio repositório dá zero resultado — o texto só existe no servidor. |
| **A forma era outra** | `🤖 Generated with [Claude Code](...)` é rodapé solto em prosa, não bloco de trailer. `git interpret-trailers` não o reconhece, e por isso ele nunca aparece em `%(trailers:only)` — é exatamente a `RN-02` da [SRS — ai-trailers list](ai-trailers-list.md), "uma exclusão que saiu de graça". |
| **O autor do rodapé era outro** | Quem escreveu o corpo do pull request não foi quem anexou o rodapé — a Forja anexa na publicação. Disciplina de quem escreve não alcança esse texto. |

### 1.3 Escopo

**Entregue:** `internal/aitrailers.Attributions`, que lê texto corrido (não trailer) em busca de três formas de marca; `internal/forge` estendido para trazer `Body` e aceitar `state` explícito; `gtr pr scan`, que cruza as duas coisas e sai com código diferente de zero quando encontra alguma.

**Fora de escopo:** reescrever ou remover o que já foi publicado — ver §4, `RN-04`.

## 2. Descrição geral

### 2.1 Posição na arquitetura

```text
internal/aitrailers/prose.go   Attributions(text) []Attribution — texto corrido, não trailer
internal/forge/pull_request.go PullRequest ganha Body
internal/forge/cli.go          PullRequests(ctx, state, limit) — state explícito, campo body pedido ao gh

cmd/pr.go                      gtr pr agrupa list e scan
cmd/pr_scan.go                 o comando: cruza forge.PullRequest com aitrailers.Attributions
cmd/pr_scan_table.go           text/document — a linha que casou vai junto, como evidência
```

### 2.2 Fluxo

1. Confere que o diretório atual é um repositório git (mesma exigência do `pr list` — é daqui que o `gh` descobre qual repositório consultar).
2. Valida `--state` localmente, antes de qualquer chamada de rede.
3. Busca os pull requests no estado pedido, com `body` entre os campos.
4. Para cada um, roda `aitrailers.Attributions` no título e no corpo; concatena os achados.
5. Descarta o que não achou nada; emite o resto na tabela, com a linha que casou.
6. Sai com erro nomeando a contagem quando achou alguma coisa — é o portão.

## 3. Requisitos funcionais

### RF-01 — Achar as três formas de marca

`internal/aitrailers.Attributions(text)` reconhece:

| Forma | Onde casa | Por quê |
|---|---|---|
| Assinatura `chave: valor` (`Co-Authored-By: Claude <...>`) | Em qualquer posição do texto | Reusa o mesmo `tool()` que `detect.go` usa para commit — prosa e commit nunca divergem sobre o que é assinatura. |
| Rodapé solto (`Generated with`/`Generated by` + nome da ferramenta) | Ancorado no **começo da linha**, depois de descartada decoração de Markdown/emoji/citação | É a forma que `git interpret-trailers` não reconhece — a `RN-02` da SRS de `ai-trailers list`. |
| Link de sessão ou de produto (`claude.ai/code`, `claude.com/claude-code`) | Em qualquer posição | Vem sem chave nenhuma na frente; só uma máquina escreve isso. |

### RF-02 — Separar atribuir de citar

Uma frase que **menciona** `"Generated with Claude Code"` no meio de uma sentença não casa — só a mesma sequência **abrindo a linha** casa. Este repositório tem um caso real dos dois lados: o corpo do PR #24 fala sobre a própria detecção e cita a frase entre aspas, no meio da linha — não casa. O PR #4 (fixture de teste) carrega o rodapé de verdade, abrindo a linha — casa.

### RF-03 — Reportar, nunca alterar

`gtr pr scan` não escreve em pull request nenhum. Reporta o que achou e sai com código diferente de zero, para servir de portão (ex.: `gtr commits check` ou um passo de CI). Sem achado, sai com `0` e uma mensagem específica.

### RF-04 — Mostrar a evidência

Cada pull request reportado vem com a(s) linha(s) que casaram, não só o nome da ferramenta. Um comando que aceita falso positivo de propósito (RF-02 admite) não pode pedir confiança sem mostrar o que comparar.

### RF-05 — Filtrar por estado, com validação local

`--state open|closed|merged|all` (padrão `open`, igual ao `pr list`). Um valor que o `gh` não aceitaria falha **antes** da chamada de rede, com o nome errado na mensagem — mesma disciplina de `branches --base` inexistente.

### RF-06 — Vale nos três formatos

`text`, `csv`/`tsv` e `json`, como todo comando do projeto (**ADR-004**). No `json`, cada pull request carrega a lista de atribuições (`tool`, `line`); no `csv`/texto, ferramentas e linhas de cada PR vêm concatenadas numa célula.

## 4. Regras de negócio

| ID | Regra |
|---|---|
| **RN-01** | **A âncora no começo da linha é o que separa atribuir de citar.** Sem ela, qualquer prosa que mencione uma ferramenta de IA seria falso positivo — inclusive a documentação que descreve esta própria detecção. |
| **RN-02** | **Decoração antes da âncora não desfaz o rodapé.** Espaço, marcador de lista, asterisco de negrito, citação (`>`) e emoji são descartados antes de comparar com `footerOpenings` — o rodapé que vazou neste repositório abria com emoji, e sem descartar isso a âncora nunca casaria. |
| **RN-03** | **Prosa e commit nunca podem divergir sobre o nome de uma ferramenta.** A assinatura `chave: valor` em `Attributions` usa o mesmo `tool()` de `detect.go`, e o rodapé solto usa o mesmo nome (`Tool`) que `Signature()` devolveria — coberto por teste (`TestAttributionsNamesTheToolTheSameWayTheSignatureDoes`). |
| **RN-04** | **Não há reescrita.** Remover ou reescrever o corpo de um pull request depois de publicado é mitigação, não apagamento — o texto já foi ao ar, diferente de um commit local que ainda não foi para lugar nenhum. E as três cláusulas da **ADR-008** não têm como valer aqui: não existe prova de recuperação para corpo de pull request, e o alcance de uma heurística sobre prosa livre não é delimitável do jeito que o alcance de um trailer é. `strip` continua restrito a trailer de verdade. |
| **RN-05** | **O estado vai explícito na chamada ao `gh`**, mesmo quando é `open` que o `gh` assumiria sozinho — mesma regra do `pr list` (§5.2 de lá), agora parametrizada em vez de fixa. |
| **RN-06** | **O campo `body` é pedido para os dois comandos do grupo `pr`, não só para o `scan`.** `internal/forge` tem uma lista de campos e um struct de resposta únicos — `list` e `scan` nunca podem divergir sobre o que é um pull request. O custo é o payload, mas ele é limitado pelo `--limit` de quem chama. |
| **RN-07** | **Nada em `internal/aitrailers` ou `internal/forge` escreve na tela.** `Attributions` devolve `[]Attribution`; `PullRequests` devolve `[]PullRequest`. Quem imprime, monta a evidência e decide o código de saída é `cmd/pr_scan.go` — mesma regra que `RN-11` da SRS de `branches`. |
| **RN-08** | **Nenhuma linha de saída termina em espaço** — `RN-10` da [SRS — branches](branches.md), com teste próprio aqui. |

## 5. Interface

```console
$ gtr pr scan --state all --limit 50
Pull requests com atribuição de autoria de IA (1):
  #39  Claude Code  [TESTE — não mergear] isca para o gtr pr scan, apagar depois
      _Generated by [Claude Code](https://claude.ai/code/session_01VW6gJjPdk4zCJMLTUJjQ6k)_
erro: 1 pull request com atribuição de autoria de IA
```

| Flag | Padrão | Efeito |
|---|---|---|
| `--state <estado>` | `open` | `open`, `closed`, `merged` ou `all` — validado antes da rede |
| `--limit <n>` | `30` | Quantos pull requests trazer |
| `--format` | `text` | `text`, `csv`, `tsv` ou `json` — os quatro da **ADR-004** |

## 7. Achado de implementação: o rodapé que o próprio servidor anexa

A primeira versão de `footerOpenings` conhecia só `"generated with"` — o texto que o Claude Code escreve. O PR #38, que introduziu este comando, veio com um rodapé **diferente**: `_Generated by [Claude Code](https://claude.ai/code)_`, sem identificador de sessão, itálico de Markdown em volta, e "**by**" no lugar de "**with**". É o rodapé que a Forja (GitHub) anexa na publicação, não o que a ferramenta escreve no corpo.

A primeira versão desta detecção não pegava esse caso — coberto por `TestAttributionsFindsTheFooterTheServerAppends`, que documenta explicitamente vir "do #38 deste repositório". A correção foi ampliar `footerOpenings` para as duas formas, e cada uma tem justificativa própria no comentário do pacote: cresce por observação, como a lista de `detect.go`, não por suposição.

## 9. Follow-ups conhecidos

- **Sem documentação prévia ao merge.** Este comando foi mergeado (PR #38) com a documentação declarada como pendente no próprio corpo do PR — este documento fecha essa pendência depois do fato, e não antes, como o resto do projeto costuma fazer.
- **`footerOpenings` cresce por observação.** Só tem as duas formas vistas na prática (`with`, `by`). Uma terceira forma de rodapé de outra ferramenta ou de uma futura mudança do GitHub não seria pega até aparecer e ser medida — mesma disciplina, mesmo risco aceito, que a lista de assinaturas de `detect.go`.
- **Sem cruzamento com `branches`/`worktrees`.** O `pr scan` não sabe se o pull request que achou corresponde a uma branch local — diferente do que o `pr list` já não faz mas o roadmap de `branches --tree` cogita (SRS de `pr list`, §9).
